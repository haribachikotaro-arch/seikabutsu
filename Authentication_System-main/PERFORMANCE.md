# 読み込み速度の調査・改善（2026-09-16）

対象: `C:\Users\slyth\Desktop\ninsyou-system`。本番ビルドは利用者が実行する方針のため、今回は実行していません。

## 原因と対処

- 開発モードでは未コンパイルのページを開くたびにコンパイル待ちが発生。標準の `npm run dev` をTurbopackへ変更しました。従来方式は `npm run dev:webpack` です。
- Yamada UIの全体エントリ経由で未使用の部品も処理。`modularizeImports` で使う部品のパッケージへ直接変換します。変換先パッケージは現在使用しているバージョンを直接依存に追加しました。
- `optimizePackageImports` も比較しましたが、このライブラリではコンパイル量が増えたため採用していません。
- ログイン・メール認証完了時の通常の内部遷移をNext.jsの `router.replace` に変更。ClerkがCookie更新用のURLを返す場合は、必要なフルページ遷移を維持します。
- 招待コード確認後の `user.reload` と追加の `router.refresh` を削除。遷移先はサーバーでユーザーと権限を新規確認します。
- ポータルリンクの先読みを無効化し、招待確認前のアクセス拒否結果を先読みしないようにしました。
- ページ遷移中の状態を表示する `loading.tsx` を追加しました。
- 実プロジェクトのUI依存パッケージに欠落があり、検証時にHTTP 500が発生。必要な下位依存を復旧しました。

## ローカル測定

一時的な検証サーバー（localhost:3101）で、依存関係を正常化してからHTTPレスポンス完了までを測定しました。ブラウザで描画が完了する時間・ログイン認証時間・本番環境の速度を示すものではありません。各方式は別々に起動して測定していますが、ファイルキャッシュ等は同一条件に固定しておらず、参考値です。

| 方式 | ホーム初回 | ログイン初回 | 新規登録初回 | 再アクセス |
| --- | --- | --- | --- | --- |
| 元のWebpack・一括インポート | 9.23秒 | 5.54秒 | 2.41秒 | 0.26～0.30秒 |
| Webpack・直接インポート変換 | 9.69秒 | 5.32秒 | 2.18秒 | 0.25～0.29秒 |
| Turbopack・直接インポート変換 | 7.25秒 | 2.13秒 | 1.73秒 | 0.36～0.41秒 |

Turbopackはこの測定で初回待ち時間を改善しました。コンパイル済みページの応答はWebpackのほうがわずかに短く、すべての状況で高速化するとは限りません。

Webpackの開発用非圧縮チャンクも比較しました。共有レイアウトは13.61MBから8.56MB、ログイン画面は12.22MBから5.37MBへ減りました。Turbopackとは出力形式が異なるため、このサイズ比較は同じWebpack同士です。本番の転送サイズではありません。
